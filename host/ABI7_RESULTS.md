# ABI v7 整理・実機確認 — 2026-11-14

`END_INPUT` とドライバーの `sealed` 状態を削除した。
ioctl 番号6は再利用せず、`ENOTTY` を返す。他の ioctl 番号・構造体・mmap は維持。
ツールは入力供給終了後に RX のみを poll し、投入件数分を回収して停止する。

## 環境

- KV260 revB、Ubuntu 24.04.5、kernel `6.8.0-1036-xilinx`。
- 既存6コア回路、コア 115,384,615 Hz、DMA 187,499,999 Hz。
- 128-bit AXI、64-byte レコード、個別 1 MiB バッファ、方向ごとに32枠のSGリング。
- 実機作業場所 `/root/fades/abi7/`。GCC 13.3.0、ツールは `-O3 -mcpu=cortex-a53`。
- 既存ファームウェアを使用。SHA-256:
  - bit: `1bc89fe1f9f3083061d277276cc28b6e7ceb0c5a59a733e2319df5677570fba8`
  - dtbo: `19b9e5ecca2c97c1fd7d4a32592e5b709c4de698cd5f55011207c57161483c4e`

## 検証

- ドライバーの実機 Kbuild `W=1` とCツールの `-Wall -Wextra -Werror` ビルド成功。
- `check_abi.py`: 削除ioctl、設定・境界・所有権・個別mmap・close/fork寿命の確認成功。
- `check_stream.py`: TX/RX=1/1、8/64、65/65 で成功。
  方向別・両方向poll、繰り返し待機、RXのみ待機でTX完了を無視、初期CPU所有面は
  完了として通知されないこと、端数排出・idle後再開・背圧・リング周回・再起動を確認。
- `check_example.py`: 有限処理49,171件の全ID・結果検証、不正入力拒否、連続投入成功。
- dmesg は overlay 解除時の既知のメモリーリーク警告と未署名外部モジュールの通知、
  probe/クロック情報のみ。DMAエラーや試験中の新たな警告なし。
