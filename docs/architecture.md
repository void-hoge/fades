# 回路構成

## PS / PL の接続

```text
PS Linux / DDR
    │ MM2S 128 bit / 200 MHz
    ▼
4 beat → 64 byte レコード組み立て
    ▼
388 bit × 64 非同期 FIFO（圧縮セル + ID、LUTRAM）
    │ 100 MHz
    ▼
81セル並列エンコーダー → 上限付き RR 配布 → 独立したソルバーコア群
                                               │
コア別 ID FIFO ← 入力成立                    結果 + 解の有無
    │                                          │
    └──────────────→ RR 結果回収・圧縮 ←────────┘
                           ▼
                 512 bit × 64 非同期 FIFO
                           │ 200 MHz
                           ▼
                 4 beat packetizer → S2MM → DDR
```

実機の現行構成は 6 コア。`solver_stream` の `CORES` はコア数、
`INFLIGHT_LIMIT` は各コアへの未完了投入数で既定値 2、`FIFO_DEPTH` は既定値 64。
現在の AXI snapshot レジスターマップと PS ツールは 6 コア構成に対応する。
コア数を変更する場合はこのマップとホスト側の検査も更新する。

入力の選択と反復は PS が決める。コアは DDR アドレスを扱わない。
空欄は全候補、ヒントは one-hot に並列変換し、行・列・ブロックからの候補除去は
コア内の推論に任せる。予約領域は入力 FIFO に保持しない。

## 配布と結果回収

- 入力 ready、未完了数が上限未満、ID を保持できるコアから RR で選ぶ。
  探索は組み合わせ回路で行い、全体で最大 1 問 / コア cycle を配布する。
- 実行中のコアにも先行投入できる。未完了数は入力成立で加算し、結果回収で減算する。
- 各コアは入力順に結果を返すため、コア別の ID FIFO を先頭から対応付ける。
- 同時結果は RR で仲裁し、1 エントリの保持レジスターから出力 FIFO へ渡す。
  出力停止中に結果・ID を変更しない。
- 全体の結果順序は回収順。入力順への大規模な並べ替え回路は持たない。

## 単一コア

候補行列は 81 セル × 9 候補 = 729 bit。
セル `i = row*9+col` が `[9*i +: 9]`、数字 `d` がビット `d-1`。

`inference.sv` は現在状態を共通解析し、Naked/Hidden Single と Locked Candidates
（Pointing/Claiming）、完成・矛盾を並列に判定する。次候補、行別変化 9 bit、
同時強制矛盾のメタデータを保持し、翌 cycle の停止判断に使う。
停止が判明した cycle の新しい推論結果は破棄する。

停滞時には `branch.sv` が 2 候補セルを優先し、同順位なら行優先で最初を選ぶ。
選択器は 81 セルを 128 葉へ置いた二分 7 段のトーナメント。
選択セルの候補を数字順で前半 `floor(n/2)` と残りへ分割し、前半から探索する。

`core.sv` の状態列は 729 bit × 1,024 の同期二重ポート BRAM deque。
先頭側に未探索の兄弟枝、末尾側に未着手の問題を保存する。
先頭キャッシュと BRAM 読み出し状態を管理し、推論中に先読みする。
ポート A は分岐保存または先頭補充、ポート B は新規問題の入力に使う。

各セルで二分による深さは最大 4 なので、未探索枝を 81 × 4 = 324 件予約する。
さらに空き判別用 1 エントリを予約し、状態列内の未着手問題は最大 699 件。
統合回路では、負荷分散のため物理容量より小さい未完了上限 2 件で制御する。

最初の解を見つけると残った兄弟枝をまとめて破棄する。
矛盾時は兄弟枝に戻り、枝がなければ解なしを 1 件出力する。
`enable=0` は探索だけを停止し、入力と既存結果の転送は独立して動作する。

## 単一コアのインターフェース

|ポート|意味|
|---|---|
|`clk`, `reset`|立ち上がり更新、同期 High reset|
|`enable`|探索の実行許可|
|`input_valid`, `input_ready`, `input_candidates[728:0]`|成立時に候補行列を受理|
|`result_valid`, `result_ready`|成立時に結果を転送|
|`result_solved`, `result_candidates[728:0]`|解の有無と行列。解なし時は解ではない|
|`queued`, `pending_branches`|状態列の占有数と未探索枝数|
|`busy`|現在の問題の処理状態|
|`event_*`|立ち上がり直前に観測する計測イベント|

ready/valid の停止中はデータを保持する。reset は実行中の問題・列・未転送結果を無効化し、
BRAM 本体を一括初期化しない。

## CDC と reset

`async_fifo.sv` は実回路に XPM async FIFO、分散 RAM、FWFT を使用する。
write / read の reset-busy と各領域の reset を扱い、初期化中のアクセスを禁止する。
各クロック領域で非同期 assert・3 段同期 deassert を使う。

XPM FWFT の先読み・出力段により、write-domain の占有数は設定深さ 64 を超えうる。
実測の最大値は 65。Verilator 用モデルは 64 エントリの抽象 Gray-pointer FIFO で、
XPM の初期化や FWFT レイテンシを cycle 単位で再現するものではない。

AXI-Lite の snapshot は core 側でカウンター群を保持してから ack を同期する。
DMA 側は同期 ack を受けて保持データを取り込む。
`solver_cdc.xdc` は同期器の最初の段と非同期 reset 端子を対象に例外を指定し、
保持 snapshot データには 5 ns の datapath / skew 上限を設ける。
クロック群全体を false path にしない。
`solver_cdc_waivers.tcl` は固定設定バス・保持 snapshot・reset 同期器について
対象と根拠を明示し、export は未レビューの Critical CDC があれば停止する。

ボードのクロック・DMA アドレス・ファン配線は [KV260 手順](../fpga/kv260/README.md)、
レコードとレジスター配置は [プロトコル](protocol.md) を参照。
